Before first query run, we have several optimizations performed at Polars level as follows:

Accounts data:

A name validation schema is applied which makes sure the names adhere to a specific pattern (Western names, given the population included in the tables) and that names including forbidden words (test, trap, etc) are not included.

An address validation schema which matches the address to a specific pattern and drops incorrect addresses.

Daily status:

Invalid changed_datetime values are removed via a filter.

The "account" column originally stored as text in the CSV files is converted to integer to match the type used by account_id in the Accounts table.

Monthly status:

The "account" column originally stored as text in the CSV files is converted to integer to match the type used by account_id in the Accounts table.

The data is then placed in 3 tables in the database, as required: Accounts, Daily_Status, Monthly_Status.
Then the Recent_Accounts table is added to the Postgres DB, as required at Step 3.
