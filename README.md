Steps taken to solve the tasks:

Project layout:

A PostgreSQL database running on a local server on my machine

Three python packages: care, validator and resources

Core package:

We have an app_setting.py module responsible for supplying the application with the necessary credentials, in this case the postgress user and password

They are stored in an env file and the following format is required:

PostgreSQL connection
APP_DATABASE__HOST=localhost
APP_DATABASE__PORT=5433
APP_DATABASE__USER=postgres
APP_DATABASE__PASSWORD=<very_strong_password_here>
APP_DATABASE__DATABASE=link_fin_db

The validation is done with Pydantic

A db_connector.py module responsible with providing an adbc connection to the PostgreSQL db

A data_loader module containing helper functions which load the from the csv files. Polaris is used to apply specific filter to daily and monthly data.

Validators package:

Contains address and name schemas responsible with filtering out bad names/addresses from the Accounts data.

These two schemas as used by polars when loading the Accounts data into a polars data frame

Resources package:

Contains only .sql files. They are used by the application to run queries on the PostgreSQL db

Other project elements:

A logger is defined at project level and can be propagated to any module, if necessary

A pyproject.toml file is defined to alleviate any potential python path issues

Data folder containing the csv files used for this exercise. Note that gitignore filters them out

Output folder containing the csv files generated by the application. Gitignore will allow them through.

Output folder containing the csv files generated by the application. Gitignore will allow them through.

Project flow:

The data is read from the the .csv files into 3 separate polars data frames

At this time, the polars will apply the name and address schema on the Accounts data and remove invalid entries. The trap is gone :)

Also, at this time, the polars will filter out entries with invalid dates in daily data

The account data is converted from string to text for both daily and monthly data

The application then checks if the tables already exist in the PostgreSQL db. If they don’t it uploads the dataframes and tables are created

In order to check if the tables are present, it queries the db with the query included in resources/table_name.sql

Once the tables are uploaded to the db, the application query_step3.sql to create the “Recent_Accounts” table and uploads it to the PostgreSQL db

At this step, the application will generate the recent_accounts.csv file in the output folder

Once this table is added, the application uses query_step5 to generate the recent_changes.csv file in the output folder

The optimization steps are performed now and detailed in the optimization.txt file.
